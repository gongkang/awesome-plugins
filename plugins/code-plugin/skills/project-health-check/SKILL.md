# 项目健康度检查

全自动分析项目完整性，使用并行子代理加速分析，生成详细的 Markdown 问题清单报告。

## 分析深度

根据用户请求选择分析深度：

| 深度 | 关键词 | 检测范围 | 预计时间 |
|------|--------|----------|----------|
| 快速 | "快速检查"、"quick"、"简要分析" | 安全漏洞、TODO/FIXME、文档完整性 | ~30 秒 |
| 标准 | 默认、"标准检查"、"完整分析" | 全部 8 个维度，基础检测 | ~2 分钟 |
| 深度 | "深度检查"、"deep"、"详细分析" | 全部维度 + 复杂度分析 + 重复代码检测 | ~5 分钟 |

## 分析维度

| 维度 | 快速 | 标准 | 深度 | 检测项 |
|------|------|------|------|--------|
| 前后端一致性 | ❌ | ✅ | ✅ | API 契约、数据模型、类型定义 |
| 技术债务 | ✅ | ✅ | ✅ | TODO/FIXME、过时依赖、代码重复 |
| 安全性 | ✅ | ✅ | ✅ | 敏感信息泄露、漏洞模式、依赖漏洞 |
| 性能瓶颈 | ❌ | ✅ | ✅ | 数据库查询、API 性能、前端性能 |
| 测试覆盖度 | ❌ | ✅ | ✅ | 测试覆盖率、关键路径覆盖 |
| 代码质量 | ❌ | ✅ | ✅ | 代码风格、复杂度、命名规范 |
| 架构健康度 | ❌ | ✅ | ✅ | 模块耦合、循环依赖 |
| 文档完整性 | ✅ | ✅ | ✅ | README、API 文档、贡献指南 |

## 工作流程

### 阶段 0: 确定分析深度

检查用户请求中是否包含深度关键词，确定分析模式。

**输出进度**:
```
🔍 项目健康度检查
📋 分析深度: 标准
📂 项目目录: /path/to/project
```

### 阶段 1: 项目检测

识别项目类型和技术栈，检测包管理器和框架配置文件。

**输出进度**:
```
📦 项目类型检测中...
  ✓ Node.js 项目 (package.json)
  ✓ TypeScript (tsconfig.json)
  ✓ React 前端
```

### 阶段 2: 并行分维度分析

**重要**: 使用子代理并行分析各维度，以提高效率。

根据分析深度，启动对应数量的并行子代理：

**快速模式 (3 个并行代理)**:
- 代理 1: 安全性分析
- 代理 2: 技术债务分析
- 代理 3: 文档完整性分析

**标准/深度模式 (8 个并行代理)**:
- 代理 1: 前后端一致性分析
- 代理 2: 技术债务分析
- 代理 3: 安全性分析
- 代理 4: 性能瓶颈分析
- 代理 5: 测试覆盖度分析
- 代理 6: 代码质量分析
- 代理 7: 架构健康度分析
- 代理 8: 文档完整性分析

**输出进度**:
```
🔄 启动并行分析代理...
  ✓ 代理 1/8: 前后端一致性 - 运行中
  ✓ 代理 2/8: 技术债务 - 运行中
  ...
```

## 子代理分析任务定义

以下是每个子代理的具体分析任务：

### 代理 1: 前后端一致性分析

**任务**: 分析项目的前后端一致性

**分析步骤**:
1. 查找 API 定义文件（OpenAPI/Swagger、GraphQL Schema、tRPC）
2. 查找前端 API 调用代码
3. 查找数据模型定义（Prisma、TypeORM、Django Model）
4. 对比检查一致性

**返回格式** (JSON):
```json
{
  "dimension": "前后端一致性",
  "issues": [
    {"severity": "high|medium|low", "location": "file:line", "description": "...", "suggestion": "..."}
  ],
  "summary": {"total": 0, "high": 0, "medium": 0, "low": 0}
}
```

### 代理 2: 技术债务分析

**任务**: 分析项目的技术债务

**分析步骤**:
1. 统计 TODO/FIXME/HACK 注释
2. 检查过时依赖（npm outdated / pip list --outdated）
3. 检测代码重复（深度模式）

**返回格式**: 同上，dimension 为 "技术债务"

### 代理 3: 安全性分析

**任务**: 分析项目的安全性

**分析步骤**:
1. 检测硬编码密钥和敏感信息
2. 检查常见漏洞模式（XSS、SQL注入、命令注入）
3. 运行依赖漏洞扫描（npm audit / pip-audit）

**返回格式**: 同上，dimension 为 "安全性"

### 代理 4: 性能瓶颈分析

**任务**: 分析项目的性能瓶颈

**分析步骤**:
1. 检测 N+1 查询模式
2. 检查 API 性能问题（缺少分页、串行请求）
3. 检查前端性能问题（包大小、懒加载）

**返回格式**: 同上，dimension 为 "性能瓶颈"

### 代理 5: 测试覆盖度分析

**任务**: 分析项目的测试覆盖度

**分析步骤**:
1. 查找测试文件
2. 运行测试覆盖率报告（如可用）
3. 识别未覆盖的关键文件

**返回格式**: 同上，dimension 为 "测试覆盖度"

### 代理 6: 代码质量分析

**任务**: 分析项目的代码质量

**分析步骤**:
1. 检查 linter 配置和警告
2. 检测代码复杂度（深度模式）
3. 检查命名规范

**返回格式**: 同上，dimension 为 "代码质量"

### 代理 7: 架构健康度分析

**任务**: 分析项目的架构健康度

**分析步骤**:
1. 检测模块耦合度
2. 检测循环依赖
3. 检查依赖方向

**返回格式**: 同上，dimension 为 "架构健康度"

### 代理 8: 文档完整性分析

**任务**: 分析项目的文档完整性

**分析步骤**:
1. 检查 README 文件
2. 检查 API 文档
3. 检查 CONTRIBUTING 和 CHANGELOG

**返回格式**: 同上，dimension 为 "文档完整性"

---

## 阶段 3: 汇总报告

收集所有子代理的分析结果后，执行以下步骤：

1. **合并问题清单**: 将所有代理返回的 issues 数组合并
2. **统计摘要**: 计算各维度的问题数量和严重程度分布
3. **排序优先级**: 按严重程度排序问题
4. **生成报告**: 使用下面的模板生成 Markdown 报告

## 报告保存位置

将报告保存到项目根目录：
- 文件名: `project-health-report.md`
- 如果已存在，添加时间戳: `project-health-report-YYYYMMDD-HHMMSS.md`

## 注意事项

1. **并行优先**: 使用 Agent 工具同时启动多个子代理分析各维度
2. **自动检测**: 尽量使用自动化工具检测，减少主观判断
3. **问题分级**: 使用 🔴 高 / 🟡 中 / 🟢 低 三级严重程度
4. **可操作建议**: 每个问题都要给出具体的修复建议
5. **只读分析**: 本技能只分析不修改，保持只读
