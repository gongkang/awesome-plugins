# 浏览器操作

本文件定义了 collector 操作浏览器的全部约定。所有站点的特殊交互逻辑集中在"站点交互专区"一节。

## 浏览器控制约定

`chrome-devtools MCP` 是单例模式，整个 MCP 服务只连接一个 Chrome 实例。`isolatedContext` 只能在同一 Chrome 内创建隔离页面上下文，不能实现跨进程并发。

- collector 是本技能唯一的浏览器控制者。
- collector 在开始站点访问前，先用 `list_pages` 检查 MCP 是否可用。
- 如果出现 profile locked、transport closed、无法列页、无法导航等浏览器基础设施故障，返回 collector 级失败，不再继续访问站点。
- 不要依赖 `isolatedContext` 做跨站并发。
- 不要默认用系统命令杀死 Chrome；除非用户明确要求调试浏览器进程。

## 单站点执行步骤

collector 对当前站点按以下步骤操作：

1. 使用 `navigate_page` 导航到配置的 URL（在同一标签页内，不要创建新标签）。
2. 检查页面中是否存在可见输入框；输入框 `uid` 每次页面加载后都会变化，不要硬编码 uid，要通过 `placeholder`、`aria-label` 或可见文本动态定位。
3. 检查阻塞项：登录提示、验证码、订阅墙、空壳页面。
4. 查阅下方"站点交互专区"，执行当前站点的特殊交互。
5. 使用 `type_text` 向输入框发送消息，并在 `submitKey` 参数传 `"Enter"`。
6. 提交后验证是否真的开始生成回答：
   - 10-15 秒内没有出现新的助手回答容器、流式文本、停止按钮或 loading 状态时，重新聚焦输入框再按一次 `Enter`。
   - 如果仍未提交，尝试点击发送按钮一次。
   - 如果页面只留下用户问题而没有助手回答，记录为 `skipped_no_answer`，不要笼统记为超时。
7. 等待回答完成（完成标志见下方"站点交互专区"）：
   - 优先观察回答区域文本是否停止明显增长。
   - 出现站点特定完成标志时提取。
   - 如果等待超时（>60秒），提取当前已生成的内容并标记 `partial`。
   - 不要死等某个特定 UI 元素；文本已停止增长且内容充足时可以提取。
8. 用 `take_snapshot` 获取页面快照，从快照的 `StaticText` 节点中提取回答内容。
9. 对带引用、来源卡片或搜索结果面板的站点，补充使用 `evaluate_script` 在回答区域附近提取 `<a href>` 完整链接；如果只能拿到域名或来源标题，在 `caveats` 记录 `source_links_low_resolution`。
10. 将当前站点结果压缩成结构化对象，然后执行浏览器清理，再继续下一个目标站点。

## 发送消息的正确方法

在 DeepSeek、Kimi 等大多数 AI 对话站点：

```text
type_text(uid="<输入框uid>", text="你的问题", submitKey="Enter")
```

不要优先使用 `fill` + 点击发送按钮的组合；在某些站点这个组合不会触发表单提交。如果 `type_text` 不可用，再尝试点击发送按钮。

## 登录态处理

chrome-devtools-mcp 连接的 Chrome 位于 `~/.cache/chrome-devtools-mcp/chrome-profile`，是一个可见的实浏览器窗口。

- 首次使用：在 MCP 的 Chrome 窗口中访问各站点，手动登录一次。
- 登录态持久性：在同一 MCP 会话内，登录态会跨页面导航保持。
- 如果某个站点出现登录墙，先检查是否已在 MCP Chrome 中登录过，再决定是否跳过。

## 站点交互专区

### DeepSeek

- **专家模式与深度思考**：提交问题前优先切换到页面上的"专家模式"，并开启"深度思考"；通过可见文本或单选按钮状态定位，不要硬编码 uid。如果控件不可见，继续提问但在 `caveats` 中记录 `deepseek_expert_mode_unavailable` 或 `deepseek_deep_thinking_unavailable`。
- **完成标志**：出现"参考 X 篇资料"或"已阅读 X 个网页"列表表示回答完成。
- **数据来源**：回答通常会给出引用链接；高时效问题优先提取数据时间和来源链接。
- **登录跳过**：如果页面跳到登录页且当前没有可用会话，以 `skipped_auth_required` 跳过。

### Qwen/Qianwen

- **等待策略**：按钮文字可能不变，观察文本区段标题是否出现（如"风险提示""总结建议"等收尾段落）；等待"停止回答"按钮消失后再提取。
- **超时处理**：如等待超 60 秒，提取当前内容并标记 `partial`。
- **登录跳过**：如需登录则以 `skipped_auth_required` 跳过。
- **高时效问题**：优先提取回答开头的数据时间点。

### Kimi

- **新建会话**：如果进入页面后没有自动开启对话（输入框为空或提示"新建会话"），需要先点击"新建会话"链接，再使用 `type_text` 输入。
- **提交验证**：提交后如果只出现用户问题、没有助手回答，重新聚焦输入框按 Enter，再尝试点击发送按钮；仍无回答则记为 `skipped_no_answer`。
- **完成标志**：出现"仅供参考"等结语时表示完成。
- **算力不足**：如出现"算力不足"提示则跳过，记录为 `skipped_ui_unavailable`（服务器过载，非技能问题）。

### 豆包

- **输入框**：`placeholder` 通常是"发消息..."，用 `type_text` 发送。
- **完成标志**：等待回答中出现"内容由 AI 生成，请仔细甄别"字样表示回答完成。
- **验证码**：如果出现验证码，记为 `skipped_captcha`，不要尝试破解。
- **登录跳过**：如果跳转到登录或订阅页面，以 `skipped_auth_required` 跳过。

## 浏览器清理

### 单站点清理
collector 在每个站点提取并压缩结果后，必须释放当前页面资源：

- 如果存在多个标签页，关闭当前任务页（使用 `close_page`）。
- 如果只剩一个标签页，导航到 `about:blank`，不要强行关闭最后一个页面。
- 不要要求用户手动关闭 Chrome 窗口，除非用户明确要求。

### 最终清理
所有站点采集完成后，必须执行最终清理：

- 关闭所有打开的任务相关标签页（使用 `close_page`，保留最后一个页面）
- 如果只剩一个标签页，导航到 `about:blank`
- 最终清理是必须的步骤，即使部分站点失败或被跳过也要执行
- 不要要求用户手动关闭 Chrome 窗口
