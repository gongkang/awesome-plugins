# 方案追问

## 明确目标和范围

从当前对话和已有资料提取目标、约束、成功标准和已定事项。意图还模糊时，先问一个开放问题，让用户描述一个真实场景或期望结果。范围明确后，聚焦会改变方案的取舍。

用可用资料和工具核实能查到的事实。需要用户补充时，问具体缺失的信息。查证期间，可以继续问不依赖该事实的问题。

## 分轮提问

1. 先问会改变方向或解锁后续决策的问题。前置条件已明确、彼此独立的问题可以合在一轮。依赖本轮答案的问题留到后续。
2. 用「Q1 · 决策主题」这样的标题给决策题编号，接着写具体问题、推荐选项和理由。有多条可行路径时，说明各自的收益和代价。用户明确委托你决定的细节可以采用合理的默认值，并标明是你的建议。
3. 每轮需要用户做选择时，优先调用当前宿主提供的原生交互提问工具（如 Codex 的 `request_user_input` 或 `request_user_input_async`，Antigravity 的 `ask_question`）。把编号、问题和选项放进卡片，推荐项排在第一位。尽量在选项说明里写清推荐理由和取舍。工具不可用时，按相同的编号和选项用文字提问。
4. 每轮提问后等用户回复。记下已确认的决定和仍待解决的问题。重要决定改变方向时，先简要复述你的理解，再据此调整下一轮问题。

## 确认结论并衔接规划

等每项关键取舍都有结论或得到用户同意延后，再按方案规模汇总已定方案、成功标准、待验证的假设和延后的事项。请用户确认你的理解。

共识确认后，涉及落地的任务优先用当前已启用或可调用的规划模式生成可审阅的实施计划，也可以交给已可用的规划技能。沿用讨论结论，只补问会影响实施的缺口。若规划模式需要用户开启，请用户在同一会话切换后继续（如 Codex 或 Antigravity 的 `/plan 根据以上讨论制定实施计划`）。没有可用的规划入口时，在对话中直接给出实施计划。计划确认后再进入已获授权的实施步骤。
