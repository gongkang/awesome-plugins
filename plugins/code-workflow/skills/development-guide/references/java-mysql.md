# Java 中的 MySQL 条款

仅在任务实际涉及 MySQL 表结构、SQL、索引或 ORM 时读取。来源版本、PDF 基线与等级含义见 [阿里巴巴手册摘要](java-alibaba.md)。下面定位均为黄山版 1.7.1 的“五、MySQL 数据库”，页码采用印刷页。

## 选定条款的执行摘要

| 原定位与等级 | 适用检查 |
| --- | --- |
| 建表规约 1–6：强制，页 32 | 新表和字段命名、布尔字段、索引名及精确小数类型按条款。 |
| 建表规约 9–10：强制，页 32 | 原文规定 id/create_time/update_time 和逻辑删除。已有不同模型时记录采用差异，不能为满足摘要自动加字段或批量修改删除行为。 |
| 建表规约 13–14：推荐，页 32 | 字段含义和状态变化同步更新注释；为了性能增加冗余字段时同时设计一致性。 |
| 索引规约 1：强制，页 33 | 真正的业务唯一性由数据库唯一索引保证，不能仅靠先查后写。 |
| 索引规约 2、4：强制，页 33 | 原文限制超过三个表的 join 及页面左/全模糊搜索；与实际查询方案不一致时列明差异，不能隐去等级或将其声称为数据库通则。 |
| 索引规约 5–7、10：推荐，页 33–34 | 根据排序、覆盖索引、深分页及隐式类型转换检查查询方案。 |
| SQL 语句 1–3：强制，页 34 | 区分行计数、去重计数和可空聚合的语义；行数统计使用 count(*)，不要与查询字段禁止通配符的条款混淆。 |
| SQL 语句 6–7：强制，页 34 | 原文禁止外键/级联和存储过程。若项目依赖这些能力，明确差异；不擅自删除约束或重写现有存储过程。 |
| SQL 语句 8–9：强制，页 34 | 数据订正先确认作用范围；多表查询或变更的列使用明确限定，防止歧义。检查条款不等于获得执行数据订正的授权。 |
| ORM 映射 1–2：强制，页 35 | 查询明确所需列；Java 布尔属性与数据库 is_ 字段正确映射。 |
| ORM 映射 4：强制，页 35 | MyBatis/iBATIS 的值参数使用绑定，避免字符串替换注入。 |
| ORM 映射 7：强制；8：推荐，页 36 | 更新维护修改时间，只变更本次允许的字段，避免大而全更新导致覆盖或越权。 |
| ORM 映射 9：参考，页 36 | 事务按实际原子性和回滚要求设置，关注缓存与搜索等外部状态，不能认为一个注解涵盖所有系统。 |

已有项目例外需说明来源、项目做法及验证依据。Java 与数据库字段类型匹配的原条款见手册“一、编程规约 / OOP 11”，不是本章建表规则的新增内容。

## 本指南的验证建议

- 动态表名、列名等不能当作普通值参数绑定的标识符使用受控映射，不把不可信输入直接拼进 SQL；返回给外部的数据按实际字段暴露边界映射，不直接暴露持久化对象。这些是本指南的补充建议。
- 从真实查询、数据量、索引和数据库版本判断性能；有现成隔离环境和权限时使用执行计划验证，避免仅凭索引名字认定命中。
- 检查 N+1、无界结果集、分页稳定性和唯一约束冲突；并发写用实际数据库语义验证，不能由 mock 测试证明。
- 验证事务边界、失败回滚、字段映射和可空聚合；结构变化需要考虑旧数据、调用方和迁移路径。
- 不在检查阶段自动连接生产库、执行迁移、订正数据或修改索引。复用项目已有测试数据和隔离方式。

本文件仅适用于上述 MySQL 场景；PostgreSQL、其他存储及其框架应查目标版本官方资料并结合项目约定。
