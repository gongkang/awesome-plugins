# TypeScript / JavaScript

本文件是本指南的工程建议；类型规则参考 TypeScript 官方文档，框架规则按项目实际版本核对。现有 JS 项目保留 JS，不因应用指南自动迁移 TS、切换模块系统或升级工具链。

## 目录与依赖

无既有约定的前端应用可从下面的概念结构开始，目录只在有对应实现时创建：

```text
src/
  app/                 启动、路由和依赖组装
  features/<业务能力>/  该能力的 UI、状态、请求与规则
  shared/              已有稳定消费者的通用 UI 或基础能力
```

Node 服务可从 `src/main` 入口、`src/modules/<业务能力>/` 和实际需要的配置/外部适配开始；在业务模块内区分协议入口、用例和数据访问，不要求每种职责都创建一个文件或类。

- 库围绕公开导出与内部实现组织，脚本可保留单文件。尊重包的 `exports`、ESM/CJS 和构建目标。
- Next.js、Nuxt 等项目使用其约定路由、服务端和客户端边界；不要为套模板迁移框架目录。
- 模块间通过约定公开导出访问；检查 re-export 是否意外暴露内部实现或形成循环。不要为了统一入口把整个代码库汇入一个巨型 barrel。
- `shared` 不依赖具体业务功能；跨业务协作应有明确方向和契约，避免隐式共享 store 或直接导入对方内部组件。

## 类型与输入

- 新 TS 项目默认启用适合目标版本的严格检查；既有项目在当前设置下改进，不批量更改 `strict` 或关闭错误来通过编译。
- 外部 JSON、表单、环境变量和存储内容需要运行时校验。优先现有校验器；`as`、泛型参数和类型注解不能证明外部值合法。
- 对未知边界值使用 `unknown` 后收窄；避免用 `any`、非空断言或双重断言隐藏缺失信息。无法立即移除的第三方类型缺口应局部隔离并说明。
- 用可区分联合表达互斥状态和错误，而不是多个可随意组合的布尔值；简单值不套入无用途的复杂类型体操。
- 明确 `null`、`undefined`、空集合和不存在的业务含义。序列化时核对可选字段、日期、金额和大整数的协议表示，不把运行时对象直接当稳定 API。

```ts
// 反例：断言没有校验请求数据。
const quantity = (body as { quantity: number }).quantity;

// 边界解析示例：输入与失败语义明确。
function parseQuantity(value: unknown): number {
  if (typeof value !== "number" || !Number.isSafeInteger(value) || value <= 0) {
    throw new Error("quantity must be a positive safe integer");
  }
  return value;
}
```

异常类型和协议错误映射沿用项目约定；不要复制示例就替换现有错误体系。

## 前端行为

- 状态放在实际拥有它的最小范围；区分本地交互、服务端数据、URL 状态和派生值，避免存多份彼此需要同步的相同状态。
- 组件表达界面和交互；复杂业务规则提取为可直接验证的函数。复用 hook 或 composable 应封装共同生命周期或行为，不只包装一次函数调用。
- 使用实际框架的副作用和清理机制处理订阅、事件、计时器及请求；考虑过期响应和组件退出。不要用副作用反复计算可以直接得到的派生状态。
- 交互包含加载、空结果、错误和重复提交的合理处理；权限最终由服务端执行。
- 性能优化根据测量或明确规模进行，不默认到处加 memo、全局缓存和复杂状态管理。

## Node 与异步边界

- 入口解析请求、认证上下文及响应；业务步骤使用显式参数和依赖。不要将 I/O、业务判断和响应拼装堆进巨型 handler。
- 每个 Promise 有明确的等待、返回或后台任务生命周期；避免 `forEach(async ...)` 导致调用方无法等待。并发批处理需考虑资源上限和部分失败。
- 远程调用明确超时、取消和有限重试；重试前确认幂等。持久化修改的事务范围与业务一致，不假设多次独立调用自然原子化。
- 在启动/组装阶段创建连接和读取配置，按现有关闭机制释放资源；不要在模块导入时暗中发起请求或连接。

## 验证与来源

从当前包脚本确认格式、lint、类型检查、测试和构建。类型检查验证静态契约，边界测试验证实际输入，交互/集成测试验证用户行为与 I/O；不以任何单项通过替代全部验证。

- [TypeScript strict](https://www.typescriptlang.org/tsconfig/strict.html)：严格检查选项随编译器版本变化。
- [TypeScript Narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html)：类型收窄和可区分联合。
- [Thinking in React](https://react.dev/learn/thinking-in-react)：仅在 React 项目应用相应组件和状态指导。
