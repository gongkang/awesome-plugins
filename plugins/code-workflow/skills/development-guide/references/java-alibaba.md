## 一、编程规约

以下是执行摘要，示例和具体语法仍需适配目标 JDK。

| 定位与原等级 | 任务中的检查要点 |
| --- | --- |
| 命名风格 2、4–7、10、12：强制，页 1–2 | 使用合适的英文业务名称与大小写；包名、异常及测试命名按条款；避免随意缩写和拼音混用。 |
| 命名风格 13：推荐，页 2 | 名称尽量完整表达用途，使调用者不用猜测。 |
| 命名风格 17.1：强制，页 3 | 基于 SOA 暴露的 Service/DAO 服务使用接口，内部实现采用 Impl 后缀；不据此给所有内部类制造接口。 |
| 命名风格 19：参考，页 3 | 方法与 DO/DTO/VO 等模型名称对应其职责，不混淆持久化、传输和展示用途。 |
| 常量定义 1：强制；4–5：推荐，页 3 | 业务魔法值有明确含义和归属；常量按功能及复用范围组织，避免巨型全局常量类。 |
| 代码格式 5、8：强制；11：推荐，页 4–5 | 手册采用 4 空格、单行不超过 120 字符；单方法总行数（不含注释）不超过 80 行属于推荐，不能升为跨语言硬门槛。与既有 formatter 冲突时说明采用差异。 |
| OOP 4：强制，页 6 | 已有外部调用的方法签名保持兼容；废弃接口说明替代方式。 |
| OOP 6–7：强制，页 6 | 相等比较考虑空值；整数包装对象的数值比较不用引用相等判断。 |
| OOP 8、10、12：强制，页 6–7 | 金额存储采用最小货币单位的整数；BigDecimal 数值比较使用 compareTo，构造时避免 double 构造器带入近似误差。 |
| OOP 11：强制，页 7 | DO 属性类型与数据库字段类型相匹配，避免字段范围超过 Java 属性可表示的值。 |
| 日期时间 1–2：强制，页 9 | 明确年份与周年份、月份与分钟、12/24 小时格式字符，避免格式模式用错。 |
| 集合处理 1、3–5、8、11、14：强制，页 10–12 | equals/hashCode 一致；toMap 明确重复键处理并关注空值；辨认 subList 视图、Arrays.asList 的结构修改限制；遍历时不直接增删被遍历集合。 |
| 并发处理 2–6：强制，页 14–15 | 线程有可追踪名称；传统线程资源按手册配置线程池；SimpleDateFormat 的共享使用安全；自定义 ThreadLocal 值使用后清理。 |
| 并发处理 8、11：强制，页 15–16 | 多资源加锁顺序一致；并发更新有防止更新丢失的实际措施。 |
| 控制语句 7–8：推荐，页 18–19 | 用清楚的分支和命名判断降低嵌套，不在条件中混入难以追踪的复杂工作。 |
| 注释规约 1–5：强制；7：推荐，页 20 | 按 Javadoc 描述声明和抽象方法契约，枚举字段说明用途；原文要求类的创建者与日期，不能伪造身份信息。代码变化时同步更新文档。 |

例如手册 OOP 10 针对业务数值相等，下列代码是本指南自拟片段：

```java
// 反例：scale 不同使 equals 返回 false。
boolean same = new BigDecimal("2.0").equals(new BigDecimal("2.00"));

// 改进：比较业务数值。
boolean sameValue = new BigDecimal("2.0").compareTo(new BigDecimal("2.00")) == 0;
```

## 二、异常日志

| 定位与原等级 | 任务中的检查要点 |
| --- | --- |
| 异常处理 2、4–7：强制，页 25 | 不用异常驱动正常流程；捕获后实际处理或传播；核对捕获异常后的事务回滚；资源在失败时也释放；finally 不返回值覆盖原结果。 |
| 异常处理 10：推荐，页 26 | 内部方法可以返回 null，但需要说明条件；这不同于前后端规约第 2 条对空列表响应的强制要求，不能混为一条。 |
| 日志规约 1、5、7–9：强制，页 26–27 | 使用日志门面和占位符，避免重复日志和直接标准输出堆栈；保留排查需要的现场及异常原因。 |
| 日志规约 14：推荐，页 28 | 对日志中的用户敏感信息脱敏；原等级为推荐，实际项目更严格的隐私约定仍需遵守。 |

用项目已有错误体系、日志归属和协议映射实现这些要求。不因为引用手册改造所有错误码或自动修改日志留存配置。

## 三、单元测试

- **强制**：第 1–7 条，页 29。测试自动执行、相互独立、可重复，有实际断言；核心增量代码的单测通过；Java 单测位于 `src/test/java`。
- **推荐**：第 8 条，页 29。原文目标为语句覆盖率 70%，核心模块语句及分支覆盖率 100%。保留原等级与核心模块条件，不因此擅改项目门槛，不只为数字编写无意义测试。
- **推荐**：第 9–11 条，页 29。用例兼顾边界、正确输入、设计及错误；数据库测试自己准备数据，并隔离或清理产生的数据。

## 四、安全规约

- **强制**：第 1–5 条，页 31。资源权限校验、敏感信息展示脱敏、SQL 参数绑定、请求输入校验及用户内容安全输出，按任务实际边界执行。
- **强制**：第 8–10 条，页 31。涉及付费或受限资源时防重放，上传验证大小与类型，配置中的密码按安全配置方案保护；不能以简单编码代替凭证保护，也不在文档记录真实凭证。

## 五、MySQL 数据库

仅在 Java 任务实际涉及 MySQL 表、索引、SQL 或 ORM 时加载 [MySQL 条款](java-mysql.md)，不将其中的字段类型和数据库惯例推广到其他数据库。

## 六、工程结构

- **推荐**：应用分层第 1 条，页 37。层次按职责依赖；Web、Service、Manager、DAO 等角色按实际需要组织。业务模块内分层是本指南的落地建议，不是手册指定的唯一包树。
- **参考**：应用分层第 2–3 条，页 37–38。异常由合适边界处理和记录；数据模型对应所属层的职责，避免逐层重复打印同一异常。
- **强制**：二方库依赖第 3–4、7–8 条，页 38。关注发布依赖的稳定性、升级引起的依赖仲裁变化和版本一致性，不因局部任务自动升级整个依赖树。
- **强制**：服务器第 1 条，页 39。远程操作有超时；具体超时值来自调用预算和项目要求，不在本技能固定。

## 七、设计规约

- **强制**：第 7 条，页 40。识别实际弱依赖及失效后的降级方式，维持核心路径；不把关键依赖失败伪装成成功。
- **推荐**：第 8–12 条，页 40。明确系统和模块边界及输入输出，考虑异常边界，单一职责、优先组合，并在实际边界运用依赖倒置。
- **参考**：第 17 条，页 41。找到并隔离真实变化点；不是预先创造所有可能的扩展层。

涉及存储设计、状态机或复杂协作时，还需回看本章第 1–6 条的适用条件及原始强制要求，按现有项目流程沉淀设计证据；不由此为普通编码附加新的审批流程。
