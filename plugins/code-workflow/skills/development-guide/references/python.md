# Python

本文件是本指南的工程建议，使用时以项目声明的 Python 版本和框架为准，不直接采用当前文档中高于目标版本的语法或 API。

## 目录与包边界

无既有约定的可安装库、CLI 或服务可采用：

```text
pyproject.toml
src/
  <package>/
    __init__.py
    <业务能力>/
tests/
```

- `src` 布局需要安装包后使用，开发环境可采用项目既有的 editable 安装方式，验证发行包时使用实际安装产物。不要用 `sys.path` 修改或全局 `PYTHONPATH` 掩盖打包问题。
- 小脚本不需要强制打包；Django 等项目保留框架的 app、配置、迁移和管理入口布局。既有 flat 布局不因小改动迁移。
- 业务能力内聚合规则及实际需要的外部适配；包的公开函数、类与模块应可辨认。`__init__.py` 不承担连接数据库、启动线程或加载整个系统的工作。
- 导入不隐式执行业务。脚本行为在明确入口执行，配置和外部资源在合适生命周期初始化。

## 类型、数据和可读性

- 公共函数、跨模块边界和复杂数据结构使用适合目标版本的类型提示。局部显然的值不必机械补全注解。
- 类型提示不会在运行时校验输入；对 JSON、配置、命令行参数及数据库外部数据使用实际解析和校验。复用已有 schema，不为每个字典引入新框架。
- 数据对象可用适合职责的 dataclass 或现有模型；只在消费者确有结构化替换需求时引入 Protocol/抽象基类，不复制 Java 的层次和接口命名。
- 不用可变对象做共享默认参数；避免依赖隐式全局状态和难以解释的动态补丁。
- 明确 `None`、空集合和异常的不同语义。金额按项目约定使用精确表示，日期说明时区；不要将浮点近似当成精确金额。
- 函数与模块遵循项目风格，命名表达业务含义；优先组合和普通函数，避免无用途的管理类。

## 异常与生命周期

- 捕获自己能处理的异常，保留原因链；不要用裸 `except` 或返回空值吞掉解析、数据库或远程调用失败。
- 文件、锁、连接及事务使用实际支持的上下文管理器或明确的清理路径，异常时也要释放。
- 异步调用应有等待、超时和取消语义；检查取消后的清理，不在异步事件循环中直接执行长时间阻塞操作。
- 注入时钟、客户端等实际外部依赖便于验证行为；不要为每个纯函数增加容器。

```python
# Python 3.9+；演示资源归属，具体解析规则按项目需要。
from pathlib import Path


def load_nonempty_lines(path: Path) -> list[str]:
    with path.open(encoding="utf-8") as source:
        return [line.strip() for line in source if line.strip()]
```

与 `open(...).read()` 后依赖垃圾回收相比，这个函数明确保证离开资源作用域时关闭文件，文件错误仍由调用方按契约处理。
